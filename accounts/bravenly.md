**Last updated:** 2026-08-13 *(was 2026-05-14)*

> ## 🔄 The play changed on 2026-08-10 — free Wayroo is now a retention lever here
>
> Everything below was written when Wayroo was a paid pitch. **It no longer is.** Under the Land-and-Expand reset, **Wayroo Essentials plus all selling tools are included with Revolution Pro at no incremental charge** (`my-gtm-context.md` §3).
>
> ### Why this account changes more than most
>
> | Prior blocker | Status now |
> |---|---|
> | **"Multiple sell attempts failed — Wayroo is C&C-only and only ~20% of Bravenly's reps are C&C"** | **The cost objection is gone.** At $0 incremental, a feature set serving 20% of the field no longer has to justify a price. **This was the only stated reason Bravenly said no.** |
> | Aice is absorbing Revolution surface area | **Aice is now a partner, launching alongside Wayroo — both free.** The combined story lands natively here because Bravenly is *already an Aice customer*; it does not have to be sold. |
> | Revolution spend ($11k+/mo) actively being reduced | **Free Wayroo makes Revolution Pro worth more.** It is the most direct available answer to Revolution surface erosion. |
> | Canada expansion unrecognised as Wayroo-shaped | Unchanged and still true — ProPay-via-Wayroo is one of the few rep-payment paths that works in Canada. |
>
> ### How to run it
>
> **Retention deployment, not evidence pilot.** Per [`outputs/07-launch-asset-plan.md`](../outputs/07-launch-asset-plan.md), these are different jobs on different scoreboards. Bravenly is a poor measurement account — ~20% C&C under-tests the selling tools, and an account reducing Revolution spend will not produce a clean adoption read. **It is a strong retention account.** Judge it on whether Bravenly stays, not on adoption rate.
>
> **The ask is the three permissions** ([`outputs/07-dso-launch-kit.md`](../outputs/07-dso-launch-kit.md)) — not a Wayroo sale. That is a materially easier conversation than the ones that failed, and it does not require reopening a pitch they have already declined twice.
>
> ⚠️ **The Aice API trade below predates the partnership and the acquisition.** Its five conditions were designed to extract Wayroo commitments in exchange for API access from a company we now intend to acquire. **Re-read before acting on it** — most of it is superseded.

## The Aice Situation (Why This Is Urgent)

Aice is integrated at Bravenly and has requested ByDesign API access so Bravenly's rep reporting can render inside the Aice app. Read plainly: Bravenly is using Aice as a cheaper, more modern surface that can progressively absorb functions currently paid for in Revolution.

**If we grant API access with no strategic frame:**
- We accelerate Revolution displacement at this account
- We get $0 in Wayroo or net-new revenue from the trade
- We set a precedent for other Aice-using clients to demand the same

**If we condition API access on a structured trade:**
- We turn Aice into a Wayroo co-seller at this account
- We capture Wayroo transaction revenue on the 20% C&C base immediately
- We use the Aice-wrapped UX to make Wayroo useful to the non-C&C 80%
- We turn a churn-risk account into a retention story

This is the active forcing function behind the broader Aice partnership conversation. See [outputs/12-partnership-program.md](../outputs/12-partnership-program.md) for the partnership program v01 structure.

## The Play

### Core trade

Grant Aice ByDesign API access for the Bravenly integration **in exchange for**:

| What Aice gets | What ByDesign gets |
|---|---|
| API access to ByDesign data so rep reporting widgets render inside Aice for Bravenly | Aice integrates a Wayroo storefront / transaction surface inside the Aice rep app for Bravenly's reps — not optional, not "future release" |
| Joint development of the rep-reporting surface inside Aice | Aice co-pitches Wayroo into Bravenly with ByDesign on the call — joint sales motion |
| Position as Wayroo + Freedom's exclusive ecommerce stack for Aice broader partnership | Bravenly becomes the first published joint case study (subject to Bravenly's approval) and proof point for the broader Aice partnership |

### Conditions on API access (must be in writing before access is granted)

1. Aice integrates a Wayroo storefront / transaction surface inside the Aice rep app for Bravenly reps — not optional, not "in a future release"
2. Aice co-pitches Wayroo into Bravenly with ByDesign — joint sales motion, not just technical integration. ByDesign on the call.
3. The Bravenly engagement becomes the first published joint case study (subject to Bravenly's approval) and the proof point for the broader partnership
4. API access is scoped to the agreed Bravenly integration surface in v01; expanded scope requires the formal Aice partnership to be signed
5. If Aice walks away from the Wayroo integration or co-pitch commitment, API access is revoked

### Why the trade nets out positive even though it concedes Revolution displacement

- **The Revolution displacement is happening regardless.** Bravenly is already paying ShapeTech for the Medusa integration and using Aice to chip at Revolution. Withholding API access doesn't stop displacement — it denies us the upside trade.
- **Trades a declining-value seat for growing-value seats.** Revolution at this account is in slow decline; Wayroo transaction revenue on the 20% C&C base is net-new revenue we currently get $0 of.
- **Cash-and-carry conversion flywheel.** Wayroo's mobile POS in an Aice-wrapped UX makes it easier for non-C&C reps to start selling on the go — likely lifting Bravenly's C&C rep share over time, which compounds Wayroo transaction revenue.
- **Roadmap features close the remaining objection.** Avalara + Dropship extend Wayroo's appeal to 100% of Bravenly's reps.
- **Canada expansion lock-in.** ProPay-via-Wayroo is the structural fit for Bravenly's Canada motion.
- **Future Wayroo↔Revolution integration** progressively converts Revolution-displacement risk into Wayroo-revenue capture over 12–24 months.
- **Retention.** An Aice + Wayroo integrated experience is materially harder for Bravenly to walk away from than the current "paying $11k/month for Revolution we don't love" status quo. The integration may itself save the account.

## Risks

| Risk | Mitigation |
|---|---|
| Bravenly accepts the Aice integration but never adopts Wayroo on the C&C base | Co-pitch motion is a contractual deliverable from Aice; if no Wayroo deal in 90 days, escalate to renegotiate API access scope |
| Aice gets API access, then doesn't deliver the Wayroo integration or co-pitch | API access conditioned in writing on integration + co-pitch deliverables; access revocable; integration scope defined before access is granted |
| API access accelerates Revolution displacement without offsetting Wayroo revenue capture | Trade structured so Wayroo transaction revenue activates in the same 0–90 day window as the integration; roadmap (Avalara, Dropship) closes non-C&C objections in parallel; Canada expansion is a parallel Wayroo growth vector |
| Other ByDesign clients see the Bravenly API concession and demand the same | Bravenly trade is explicitly tied to the formal Aice partnership and its integration + co-pitch deliverables; not a generic API-access policy change; communicate as a partnership pilot, not a precedent |
| Bravenly churns Revolution before Wayroo revenue compensates | Even partial Revolution displacement that's offset by Wayroo transaction revenue + integration-driven retention is a better outcome than the current trajectory (full Revolution churn, $0 Wayroo) |
| Bravenly's Metrix Global processor commitment blocks Wayroo cart adoption | Wayroo's value at Bravenly is on the C&C / mobile-POS / ProPay individual-merchant side, not the ecommerce cart side. The cart conversation can stay deferred; we don't need to win the cart to win the rep transaction layer |
| Aice partnership stalls before Bravenly trade closes | Bravenly trade can stand on its own as a bilateral integration agreement scoped to this account; partnership formalization is upside, not a prerequisite |
